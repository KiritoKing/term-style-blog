# blog-post-pages

## Why

站点需要以“文件系统/终端”风格浏览帖子内容，因此必须明确帖子数据模型、列表与详情页的路由与渲染行为，确保静态构建与导航一致。

## What Changes

- 新增本能力的规格文档，用于锁定帖子内容与页面行为

## Impact

- 相关代码：`src/data/posts.ts`、`src/pages/posts/index.astro`、`src/pages/posts/[id].astro`

## ADDED Requirements

### 需求:帖子必须基于静态数据源定义
系统必须在构建期从静态数据源读取帖子列表，每个帖子必须包含 `id`、`title`、`date`、`category`、`tags`、`content` 字段。

#### 场景:读取帖子列表
- **当** 构建或渲染页面需要帖子数据
- **那么** 系统必须以 `id` 作为唯一标识读取帖子

### 需求:帖子列表页必须展示全部帖子并可进入详情
系统必须在 `/posts` 页面列出全部帖子条目，并提供指向 `/posts/<id>` 的链接。

#### 场景:浏览帖子列表
- **当** 用户访问 `/posts`
- **那么** 页面必须为每个帖子渲染一个条目
- **那么** 每个条目必须包含指向 `/posts/<id>` 的可点击链接

### 需求:帖子详情页必须静态生成并渲染内容
系统必须为每个帖子 `id` 生成静态详情页，并在 `/posts/<id>` 显示标题、日期、分类、标签与正文内容。

#### 场景:静态路径生成
- **当** 站点执行静态构建
- **那么** 系统必须为每个帖子 `id` 生成对应的 `/posts/<id>` 路由

#### 场景:阅读帖子详情
- **当** 用户访问任意 `/posts/<id>`
- **那么** 页面必须显示该帖子的 `title` 与 `content`
- **那么** 页面必须显示该帖子的 `date`、`category` 与 `tags`

### 需求:详情页必须提供返回帖子列表的入口
系统必须在帖子详情页提供返回 `/posts` 的导航入口。

#### 场景:返回上级目录
- **当** 用户在帖子详情页点击返回入口
- **那么** 页面必须跳转至 `/posts`
