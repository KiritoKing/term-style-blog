## 上下文

当前项目同时存在 Astro 与 React 渲染环境，图标来源统一为 lucide，但 Astro 侧提供商需要切换到 Iconify 以简化配置并保持静态渲染优先。React 侧现有 lucide-react 使用已稳定，需保持不变并确保两端图标视觉一致。约束包括：最小化客户端 JS、保持 UI 视觉一致、路径别名 @ 指向 src。

## 目标 / 非目标

**目标：**
- Astro 侧使用 Iconify 作为图标提供商，图标集仍为 lucide
- React 侧继续使用 lucide-react，避免破坏现有组件接口
- 统一图标样式与命名，减少双端差异

**非目标：**
- 不引入新的图标集或替换 lucide
- 不重构现有 React 组件结构
- 不引入全站客户端渲染

## 决策

- 在 Astro 中采用 Iconify 提供商以提供服务器渲染友好的图标渲染能力，并继续使用 lucide 作为图标集，保证一致的图标库来源
- 在 React 中保持 lucide-react 不变，避免更改交互组件的调用方式与 bundle 结构
- 通过集中配置与统一图标命名映射，减少跨框架的维护成本

## 风险 / 权衡

- Iconify 与 lucide-react 的渲染细节可能存在细微差异 → 在关键页面核对图标尺寸与 stroke 视觉，并对 Astro 侧进行必要的样式补偿
- Astro 侧替换提供商可能影响现有使用方式 → 保留统一的图标封装入口以降低替换成本
