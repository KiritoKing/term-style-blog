## 上下文

项目使用 Astro 静态渲染为主，列表页面集中在 src/pages/posts、src/pages/tags、src/pages/categories。当前所有列表均一次性渲染全量文章或聚合结果，缺少分页与页码路由。数据层聚合与过滤集中在 src/data/blog.ts，适合扩展分页切片逻辑。目标是在保持终端风格与最小化客户端 JS 的前提下，实现静态分页输出。

## 目标 / 非目标

**目标：**
- 为文章列表、标签/分类列表、标签/分类详情页提供一致的分页体验
- 使用静态路由与构建期分页输出，避免客户端分页
- 复用统一的分页计算与渲染组件，降低重复代码

**非目标：**
- 引入无限滚动或客户端加载更多
- 改变现有文章排序规则或标签/分类计算规则
- 引入新的外部依赖

## 决策

- 使用 Astro 的 getStaticPaths + 路由参数生成分页页码，而非客户端分页，以符合静态渲染与最小化 JS 的要求
  - 备选方案：客户端分页组件或 CSR 列表更新
  - 未选原因：增加 JS 负担，违背项目风格与性能目标
- 在 src/data/blog.ts 中新增分页切片与页码计算工具，页面层只负责调用与渲染
  - 备选方案：各页面各自计算分页
  - 未选原因：重复逻辑且难以保持一致性
- 新增通用分页导航组件（Astro 组件）用于各列表页面复用
  - 备选方案：每个页面单独编写分页 UI
  - 未选原因：样式与交互一致性难以保证

## 风险 / 权衡

- 静态分页会增加构建时生成的页面数量 → 通过统一 perPage 配置控制页码规模
- 标签/分类详情页的分页需要更多路由输出 → 采用与现有 slug 路由一致的 getStaticPaths 组织方式
- 分页导航组件需要兼容不同列表路径 → 以基础路径 + page 参数构造，避免页面内硬编码
