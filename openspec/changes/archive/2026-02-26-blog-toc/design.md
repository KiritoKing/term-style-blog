## 上下文

当前博客详情页在 [id].astro 中渲染内容与元信息，正文使用 `prose-terminal` 做统一排版。目录能力需要在正文之外生成结构化导航，同时保持终端风格视觉一致，并避免引入全页面 React。项目已有像素风容器样式（`pixel-panel`）与字体体系，可复用以对齐参考模板的视觉语言。

## 目标 / 非目标

**目标：**
- 在博客详情页生成并渲染正文目录，目录数据直接来自文章 content 的标题层级。
- 目录样式与参考项目视觉一致，优先复用当前项目的终端风格样式体系（如 `pixel-panel`、字体与颜色体系）。
- 目录默认静态渲染，仅在必要时引入最小客户端逻辑。

**非目标：**
- 不引入全页面 React 渲染或复杂的客户端滚动监听。
- 不修改内容来源（Notion）或内容存储结构。

## 决策

- 使用 Astro 内容渲染产物中的 headings 元数据生成目录结构，并与正文锚点保持一致，避免二次解析正文 HTML。
  - 备选：在构建阶段对正文 HTML 做标题提取。未选用，因为 Astro 已提供渲染辅助数据，减少解析逻辑。
- 目录作为独立组件插入详情页布局，使用现有样式体系实现终端风格一致性。
  - 备选：将目录嵌入正文内容中。未选用，因为目录需要独立布局与固定视觉层级。
- 若文章无可用 headings，则不渲染目录区域，避免空占位。
  - 备选：渲染空状态提示。未选用，因为会增加视觉噪声。

## 风险 / 权衡

- 若内容渲染未提供 headings 元数据，需要调整到可提取的渲染接口 → 缓解：在实现阶段优先验证 `render(post)` 的返回结构，必要时采用安全的标题提取方案。
- 目录样式对齐参考模板但模板内无明确 TOC 结构 → 缓解：复用 `pixel-panel` 与 `prose-terminal` 字体/颜色体系，确保整体一致性。
