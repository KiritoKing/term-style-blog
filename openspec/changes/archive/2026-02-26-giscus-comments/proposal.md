## 为什么

当前站点的文章页缺少可持续的评论系统，导致读者无法在阅读路径中完成反馈闭环。引入基于 GitHub Discussions 的 giscus，可以在不增加自建后端与数据库的前提下，提供评论与反应能力，并通过自定义主题将评论区视觉与站点“像素风 + 命令行 UI”统一。

## 变更内容

- 在文章详情页接入 giscus 评论区，并确保仅在需要的页面加载（不全站注入）。
- 增加评论区主题能力：以站点现有视觉规范为基准，提供与终端风格一致的 giscus 主题样式，并同时适配浅色与深色主题。
- 提供必要的运行与运维约束：仓库 Discussions 开启、giscus app 安装、公开可见性与可选的 origin 限制策略。

## 功能 (Capabilities)

### 新增功能
- `giscus-comments`: 在文章页嵌入 giscus 评论与反应，并与页面路由建立稳定映射关系。
- `giscus-terminal-theme`: 提供与站点“像素风 + 命令行 UI”一致的 giscus 自定义主题样式，并支持浅色与深色主题的切换策略。

### 修改功能
无

## 影响

- 受影响页面：文章详情页（`/posts/[id]`）渲染结构需要新增评论区占位与布局。
- 受影响样式：需要新增 giscus 主题样式文件与少量容器布局样式，保持与全站视觉一致，并覆盖浅色与深色主题。
- 外部依赖：依赖 GitHub Discussions 与 giscus app；评论发布走 GitHub OAuth 授权流程。
- 运行时行为：新增一个第三方脚本与 iframe（giscus），需要关注 CSP、加载性能与跨站限制（可选 origins/originsRegex）。
