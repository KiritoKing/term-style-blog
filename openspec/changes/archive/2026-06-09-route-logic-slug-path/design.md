## 上下文

当前帖子列表与详情页路由基于 `id` 生成，页面位于 `src/pages/posts/index.astro` 与 `src/pages/posts/[id].astro`。需求是调整路径优先级：若帖子存在 `slug`（或等价 path 字段）则使用 slug 作为路由，否则回退使用 id。需要在列表链接与静态路径生成处保持一致，以避免导航与静态构建路径不一致。

## 目标 / 非目标

**目标：**
- 统一帖子详情与列表链接的路径偏好规则：slug 优先、无 slug 时用 id。
- 保持 Astro 静态生成能力与现有页面结构不变。
- 将路由拼接规则集中，降低重复与偏差。

**非目标：**
- 不引入新的页面层级或重构页面组件结构。
- 不新增客户端重定向或服务端 rewrite 规则。
- 不更改帖子数据模型字段含义，仅在路由生成时读取 slug。

## 决策

- **集中路由拼接规则**：将 slug/id 选择逻辑封装为单一函数，供列表链接与 `getStaticPaths` 复用，避免出现路径不一致。
  - 备选方案：分别在列表页与详情页内联判断。
  - 取舍原因：集中逻辑更易测试与维护，符合最小改动原则。
- **保留 `id` 作为回退**：当帖子缺少 slug 时仍使用 `id`，保证旧数据集可用。
  - 备选方案：强制要求 slug 存在并在构建期报错。
  - 取舍原因：避免破坏性变更，兼容现有数据。

## 风险 / 权衡

- slug 可能与 id 冲突或重复 → 在路由构建时优先 slug，但保留唯一性校验的日志/构建期断言作为后续优化。
- slug 缺失比例较高 → 仍回退使用 id，行为与当前保持一致，风险可控。
