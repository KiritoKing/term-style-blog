## 上下文

首页系统信息、侧栏 network、about 内容目前均为页面/组件内静态写死。需要在保持 Astro 静态渲染与最小客户端 JS 的前提下，将数据来源配置化，并在首页引入基于浏览器真实信息的系统信息展示。

## 目标 / 非目标

**目标：**
- 首页系统信息改为浏览器端动态生成，呈现接近 neofetch 的信息结构
- 侧栏 network 改为数组配置驱动，支持图标、文案、链接
- about 数据改为配置驱动，集中维护

**非目标：**
- 不引入新的外部依赖或 UA 解析库
- 不追求完全等同原生系统信息（浏览器限制）
- 不改动整体页面结构与视觉风格

## 决策

- 使用轻量客户端组件渲染系统信息：在首页引入一个小型 React 组件（或 Astro + client:load 的交互组件），仅负责读取 `navigator`/`screen`/`Intl` 并输出字段。理由：系统信息只能在浏览器端读取，且该区域需要实时生成。
- 统一配置数据来源：新增 `src/data` 下的配置模块，导出 network 配置数组与 about 数据对象，页面/组件通过 `@/data/...` 引用。理由：集中维护，避免分散在页面中硬编码。
- 保留静态兜底：系统信息区域在未水合或 JS 禁用时展示占位默认值。理由：保证静态渲染可用与首屏结构稳定。

## 风险 / 权衡

- 浏览器可用信息有限 → 通过字段命名与展示策略弱化“系统级”承诺
- 客户端水合带来少量 JS → 仅对系统信息区块水合，避免全页 React
- 各浏览器字段差异 → 提供简单兼容分支与空值回退
