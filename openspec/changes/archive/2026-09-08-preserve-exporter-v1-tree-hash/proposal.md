# Change: Preserve exporter v1 tree-hash compatibility

## Why

The real Deno exporter computes schema-v1 `source_tree_hash` from entries ordered as `slug,status,title,path,bytes,sha256`. The Node consumer reconstructs the same values in a different property order before `JSON.stringify`, so every real immutable snapshot fails with `TREE_HASH_MISMATCH`. Its recursive discovery can also disagree with the producer's global path sort when both `a.md` and `a/child.md` exist.

## What Changes

- Reconstruct hash entries in the established exporter-v1 property order without changing producer bytes or hashes.
- Globally sort discovered Markdown paths before comparing them with the manifest.
- Add a committed synthetic golden snapshot generated by the actual Deno exporter, with provenance and nested/Unicode/public-status coverage.
- Keep malformed manifests, byte tampering, immutable inputs and manual-preview/production policy fail closed.

## Impact

- Modified capability: `publication-deployment` consumer validation only.
- No exporter, workflow policy, content, generated site, credential, remote or Git mutation.
