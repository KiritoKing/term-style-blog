# terminal-command-ui

## Purpose

定义终端命令面板的输入输出、交互与路由联动行为，确保跨页面体验一致。

## Requirements

### 需求:终端必须提供命令输入与输出区
系统必须在页面底部渲染终端输出区与输入框，并展示提示符 `guest@server:{promptPath} $`。

#### 场景:终端基础显示
- **当** 页面加载完成
- **那么** 终端输出区必须显示至少一条提示信息
- **那么** 输入框必须可聚焦并接受键盘输入

### 需求:终端必须支持命令历史回溯
系统必须保存已执行命令并支持通过方向键回溯历史输入。

#### 场景:向上回溯历史
- **当** 用户已执行至少一条命令
- **并且** 用户按下 ArrowUp
- **那么** 输入框必须显示最近一次执行的命令

#### 场景:向下退出历史
- **当** 用户处于历史回溯状态
- **并且** 用户按下 ArrowDown 直至到达末尾
- **那么** 输入框必须恢复为空

### 需求:终端必须支持命令自动补全
系统必须在用户按下 Tab 时根据当前输入执行命令补全或输出候选。

#### 场景:唯一命令补全
- **当** 用户输入 `he` 并按下 Tab
- **那么** 输入框必须自动补全为 `help `

#### 场景:多候选输出
- **当** 用户输入 `c` 并按下 Tab
- **那么** 终端输出必须显示所有匹配的命令列表

### 需求:终端输出必须在页面跳转前持久化
系统必须在发生路由跳转前将终端输出与历史记录写入本地存储。

#### 场景:执行导航命令
- **当** 用户执行 `cd posts`
- **那么** 系统必须在跳转前持久化终端输出与历史

### 需求:终端命令必须与路由导航联动
系统必须根据输入命令在必要时触发页面跳转，并在输出区回显执行结果或错误信息。

#### 场景:进入 posts 列表
- **当** 用户在任意页面输入 `cd posts`
- **那么** 终端输出必须包含目录切换提示
- **那么** 页面必须跳转至 `/posts`

#### 场景:读取帖子文件
- **当** 用户在 posts 列表页输入 `cat <post-id>.md`
- **那么** 终端输出必须包含读取提示
- **那么** 页面必须跳转至 `/posts/<post-id>`

#### 场景:未知命令报错
- **当** 用户输入未支持的命令
- **那么** 终端输出必须以错误样式显示 `command not found` 信息

### 需求:终端必须支持基础内建命令集合
系统必须至少支持以下命令：`ls`、`dir`、`cd`、`pwd`、`cat`、`clear`、`echo`、`whoami`、`date`、`help`、`grep`。

#### 场景:清屏
- **当** 用户输入 `clear`
- **那么** 终端输出必须被清空

#### 场景:帮助信息
- **当** 用户输入 `help`
- **那么** 终端输出必须列出可用命令及简要说明

#### 场景:执行 grep 命令
- **当** 用户输入 `grep <query>`
- **那么** 终端输出必须提示正在执行 grep 搜索
- **那么** 页面必须跳转至 `/search?q=<query>`

#### 场景:grep 缺少参数
- **当** 用户输入 `grep` 且未提供查询内容
- **那么** 终端输出必须提示正确用法
